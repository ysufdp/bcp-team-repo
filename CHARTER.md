# Team Charter

## 1. Purpose
Our team aims to explore emerging software engineering paradigms throughout this term, execute weekly lab deliverables, and develop a feasible, thesis-worthy project

## 2. Roles & Responsibilities
*(Roles will be formally assigned following group confirmation)*

* **Project Lead / Repository Admin:** Oversees repository management, pull request reviews, and overall project coordination.
* **Documentation Lead:** Responsible for maintaining project write-ups, `README.md`, `CHARTER.md`, and proposal drafts.
* **Technical Lead / Developer:** Leads environment setups, code implementations, and notebook execution.
* **Quality Assurance (QA) & Testing Lead:** Validates deliverables, enforces file naming conventions (`surname_component.png`), and reviews branch merges.

## 3. Working Norms
* **Communication Channel:** Primary communication takes place via Discord / Messenger for daily syncs and announcements.
* **Response Time Expectations:** Team members should acknowledge messages within 12–24 hours on weekdays and during scheduled lab hours.
* **File & Repository Storage:** All source code, lab screenshots, and documentation must reside in this official GitHub repository (`bcp-team-repo`). External assets reside in the `docs/` folder.

## 4. Decision-Making Process
* **Consensus First:** Major decisions (e.g., final thesis topic selection) will be made by team consensus.
* **Majority Vote:** If consensus cannot be reached, decisions will be finalized via a simple majority vote.
* **Accountable Role Decides:** Technical or documentation implementation specifics fall to the designated lead for that task.

## 5. Conflict Resolution Process
1. **Private Discussion:** Address issues directly and privately between the involved team members first.
2. **Team Sync:** If unresolved, bring the issue to a full team discussion to reach an internal resolution.
3. **Instructor Escalation:** If the issue persists or impacts project progress, escalate the matter to the course instructor.

## 6. Quality & Tracking
* **Definition of Done (DoD):** A lab task is considered complete only when:
  * All code and notebooks execute without errors.
  * Required screenshots strictly follow the `surname_component.png` format.
  * Changes are pushed via a feature branch and merged through an approved Pull Request.
* **Task Assignment & Tracking:** Tasks and lab requirements are distributed during weekly meetings and tracked within GitHub Issues / project boards.
